4 Quy Tắc Sống Còn

Tuân thủ 4 quy tắc này để AI không "ngáo" và hệ thống không bị phá.

01
🎨 Design First, Code Later
Bắt buộc vẽ State Machine, ERD, API Flow bằng Mermaid TRƯỚC khi gõ code. Boss duyệt thiết kế mới được code.
02
🧠 Trị Bệnh Não Cá Vàng
Mỗi session AI mới → LUÔN nạp SYSTEM_ARCHITECTURE.md + SCHEMA_FROZEN.md. AI quên = AI bịa = PHÁ HỆ THỐNG.
03
✂️ Chia Nhỏ Prompt
KHÔNG yêu cầu AI làm A-Z. Chia 4 bước: DB → Sync → API → UI. Checkpoint verify sau mỗi bước.
04
🔄 Git Revert, Không Sửa Đè
AI sửa lỗi bằng cách đè code → nát file. Dùng git revert → mở session mới → code lại. Bắt AI self-review trước commit.

Slide 5

Kỷ Luật Git

Quy trình commit, branch naming, và cách xử lý khi AI "phá".

📝 Commit Format

[AUUS1] feat: add order sync
[ZEN8] fix: handle duplicate ID

Format: [PROJECT] type: message

🌿 Branch Naming

feature/auus1-order-sync
feature/zen8-dashboard

Format: feature/[project]-[feature]

🔍 AI Self-Review

Trước khi commit → Bắt AI review code theo checklist 6 mục.

Kiểm tra: vùng lãnh thổ, imports, naming, SQL injection, error handling, credentials.

🚨 Khi Code Bị Nát

❌ KHÔNG bắt AI sửa đè
✅ git revert HEAD
✅ Mở session AI mới
✅ Nạp context lại từ đầu
✅ Code lại feature

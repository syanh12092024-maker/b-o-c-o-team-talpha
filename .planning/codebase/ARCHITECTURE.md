## Key Components

### `faos_brain/analyst.py` (23KB)
- Executive Analyst agent (Pillar 2)
- Reads BigQuery metrics, detects anomalies
- Produces structured analysis reports

### `faos_brain/marketing_director.py` (30KB — largest file)
- Marketing Director agent (Pillar 3)

### `faos_brain/runner.py` (8.7KB)

### `faos_brain/llm_client.py` (8.6KB)

### `faos_brain/optimization/`

## Data Flow

```
Meta API ──→ sync_auus1_ads.py ──→ BigQuery (raw ads table)
Poscake  ──→ sync_auus1_orders.py → BigQuery (orders table)

BigQuery ──→ analyst.py (reads metrics)
analyst.py → marketing_director.py (decision input)
marketing_director.py → director_comms.py → Telegram (human approval)
Telegram callback → webhook_server.py → director_execution.py → Meta API
                                      → FalkorDB (memory store)

BigQuery ──→ FastAPI (api/) ──→ SSE stream ──→ Next.js Dashboard
```

## Agent Configuration Pattern

Projects configured via:
- `.env` file (credentials per project: `AUUS1_*`, `ZEN8_*`, etc.)
- `config/projects/` (YAML config per project)
- Running flag `--project auus1` selects the active project

## Database Strategy

- **BigQuery**: Immutable analytics logs (append-only via scripts)
- **FalkorDB**: Mutable agent memory (read/write via graph queries)
- Schema frozen policy: changes to BQ tables require `SCHEMA_FROZEN.md` review

## Multi-Project Support

Dashboard supports: `auus1`, `zen8`, `stramark`, `t1`, `hnle`, `talpha`, `trendify`
Each project has isolated credentials, ad accounts, and BigQuery datasets.

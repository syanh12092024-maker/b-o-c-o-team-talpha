## Language Conventions

### Python (backend / scripts)

- **Style**: PEP 8, type hints throughout
- **File naming**: `snake_case.py` (e.g., `sync_auus1_ads.py`, `llm_client.py`)
- **Class naming**: PascalCase (e.g., `MarketingDirector`, `LLMClient`)
- **Constants**: UPPER_SNAKE_CASE
- **Config**: Always loaded from `.env` via `python-dotenv`, centralized in `faos_brain/config.py`

```python
# Typical pattern in scripts
from faos_brain.config import Config
config = Config()
project_id = config.project_id  # e.g., "auus1"
```

### TypeScript/React (frontend)

- **Style**: TypeScript strict mode
- **Component naming**: PascalCase (e.g., `AdminHome`, `MarketingTab`)
- **File naming**: `kebab-case.tsx` for components
- **Types**: Centralized in `types.ts` files per feature
- **Hooks**: `use-*.ts` naming

```typescript
// Typical component pattern
interface Props { projectId: string }
export default function MarketingTab({ projectId }: Props) { ... }
```

## Architecture Patterns

All sync scripts follow this pattern:
```python

    # 1. Load credentials from config
    # 2. Fetch from external API
    # 3. Transform data
    # 4. Upload to BigQuery
    # 5. Log results to Discord/console

if __name__ == "__main__":
    sync_project("auus1", dry_run=False)
```

### BigQuery Pattern

- **Raw tables**: Synced from APIs (write via scripts)
- **Views**: Computed metrics (`vw_*` prefix)
- **Schema**: NEVER alter tables — schema is frozen (`docs/SCHEMA_FROZEN.md`)
- All queries use project-specific dataset prefixes

```python
# Standard BQ query pattern
from google.cloud import bigquery
client = bigquery.Client(project=config.bq_project_id)
query = f"SELECT * FROM `{config.bq_dataset}.table` WHERE ..."
df = client.query(query).to_dataframe()
```

## Environment Config Pattern

- All secrets in `.env` (never in code)
- Per-project credentials prefixed: `AUUS1_*`, `ZEN8_*`, `T1_*`, `HNLE_*`, etc.
- `Config` class in `faos_brain/config.py` is single source of truth

## Error Handling

- LLM calls always wrapped in try/except with fallback chain
- BigQuery errors logged to Discord webhook
- `faos_brain/runner.py` has global error handler that sends Telegram alert
